# Roadmap: is a set of ANNs better than one ANN for the GA18 chemistry?

Written 2026-11-02 (Spain time, CET). Status: **plan only**. No training or CFD job has been run for it. Every stage marked *heavy* waits for Javier's go-ahead.

## 1. The question

Today one network (ResNet-FiLM, hidden 192, 3 FiLM blocks, physics layers for element conservation and the NASA temperature solve) maps `(Y, T, P, h, dt) -> Y(t+dt)` over the whole burner space: non-premixed CH4/air, 1 atm, T 300 to about 2120 K, Z 0 to 1, GA18.

The question is whether **several networks**, each responsible for part of the space or part of the output, plus a selector (gate) that decides which one(s) to use for each cell, represent this chemistry better than the single network, at an inference cost the CFD can afford.

"Better" is judged in the same way the project already judges single networks: the offline Cantera benchmark (stage 18) to screen, and the fixed CFD protocol v1 in **pure** mode to decide.

### Why it might help (evidence from earlier work)

- The remaining error is concentrated in a few places that behave very differently from each other:
  - radicals near equilibrium (OH 100 to 1000 % one-step error in ood7, OH x2.2 to x2.5 in ITERML iteration 3);
  - CO in cooled lean gas at 400 to 1000 K (ITERML iteration 2, CO x6.4);
  - ignition timing near the nozzle (early ignition of ood1/ood8/ISANN v6, late ignition of ITERML iteration 1).
- These regions have different time scales and different "active" species. One network with one set of weights must fit fast ignition chemistry, slow CO oxidation in cold gas and the near-zero increments of equilibrium at the same time. The equilibrium fixed-point losses (PR #15) showed the conflict directly: making radicals better near equilibrium made the coupled flame temperature worse (cold bias of -7 to -13 K).
- Cluster-based multi-network tabulation is an established idea in combustion (for example SOM-partitioned multiple MLPs in Franke et al., Combust. Flame 2017, and Ding et al., Combust. Flame 2021), and mixtures of experts (Jacobs et al., Neural Computation 1991) and deep ensembles (Lakshminarayanan et al., NeurIPS 2017) are standard ML tools. *(Check the exact references before using them in a paper.)*

### Why it might not help

- **Seed noise is as large as the differences we try to measure.** ood1 seeds give dT_10ms 33 to 60 K and ood6 seeds 22 to 62 K in the benchmark. Any ensemble result must beat the seed spread, not one lucky seed.
- **The offline benchmark does not predict the CFD ranking** (Spearman 0.28 to 0.77; it ranked ITERML iteration 2 better, and it was worse in CFD). Offline gains are only a filter.
- **Boundaries between experts can create jumps** in the predicted increment. In the coupled CFD a cell that oscillates across a boundary may see a noisy source term, which could be worse than a smooth, slightly less accurate single network.
- Each expert sees less data. The thin regions (lean side, ignition, psi < 0) get thinner per expert.

## 2. Fixed rules for this work

1. **Training data stays physics-based.** Every expert, the gate and any residual network is trained only on the a priori thermochemical exploration (regimes 0 to 9 of stage 04, plus the ITERML seeded regimes 10 to 14, whose pairs are generated by Cantera from physics reactors; the CFD states themselves are only seeds and stay excluded). No CFD or DI pairs, ever, in this line of work. ISANN-style online training is out of scope.
2. **If an expert's region is under-sampled, fix it with exploration** (more reactors or seeds in that region), never with CFD data.
3. **Partitions are defined on the input state only** (T, Z, progress variable, distance to equilibrium, VQ-PCA cluster). The regime label of a training pair describes how it was generated, and a CFD cell has no such label, so the gate cannot use it.
4. **Controlled comparison.** An ensemble and its single-ANN baseline use the same training pairs, the same physics layers, the same scalers, and the same number of seeds.
5. **Comparisons by seed spread, not by one run.** Offline: 3 seeds. CFD: 2 seeds, with the ITERML elitism rule (both seeds of the candidate must beat the best baseline by more than the spread).

## 3. Baselines

| Baseline | Why | Data available |
|---|---|---|
| **ood8** (single ResNet-FiLM) | Best a priori model in the OOD loop (hybrid 3.4 K at 50 ms) | `chemmanifold/handoff-ood8/` |
| **ITERML iteration 1** | Best pure-mode CFD so far (flame 3.3 K, S 2.22) | Results in `chemmanifold/iterml/iter1/`; the training data lived in the ITERML container and must be handed off first |
| ood1, ood6 seed sets (3 seeds each) | Already in the benchmark; used for the cost-free stage E0 | `chemmanifold/benchmark/semillas/` |

Two single-ANN controls are trained next to every ensemble candidate:

- **cost-matched**: same arithmetic per cell as the ensemble at inference (for a hard gate this equals one expert; for a soft gate it equals the experts that are evaluated);
- **parameter-matched**: one network with the same total number of weights as all experts together.

Without both controls, an ensemble win could just mean "more parameters".

## 4. Candidate strategies

Ordered from cheapest to most complex. Each one has a short reason tied to the error map above.

### P0. Deep ensemble (average of seeds)

M networks of the same architecture, trained with different seeds on the same data; the step is their average (in Box-Cox space, followed by the usual element projection and T solve). Members can also be trained on bootstrap resamples.

- Attacks the seed noise directly. The averaged prediction is usually better than the average member.
- The disagreement between members is a free **uncertainty signal**. It could become a new OOD bit (`CM_OOD_DISAGREE`) in the UDF. This matters in Fluent, which has no DI fallback: today OOD there can only flag a cell.
- Cost M times one network. M = 3 is about 3x the network part of the step.

### P1. Hard partition by physical variables

Two to four experts, split by temperature bands (for example cold below T_freeze, an ignition band around 800 to 1700 K, hot near-equilibrium above about 1600 K) or by progress variable c and Z.

- Simple, interpretable, matches the three error regions.
- Each region gets its own scalers (Box-Cox lambda, sigma of increments). Near equilibrium the increments are tiny, so a dedicated sigma alone may fix part of the radical problem.
- Boundaries need **overlap and blending**: train each expert on its band plus a margin, then blend the two outputs linearly across the overlap (a partition of unity), so the step is continuous.

### P2. VQ-PCA clusters as experts

One expert per VQ-PCA cluster (K = 4 to 8; stage 06 already fits K-means clusters and the UDF already stores the cluster tables for the OOD manifold check).

- The gate is the nearest centroid, which the UDF computes anyway, so the gate is almost free.
- Data-driven boundaries follow the manifold better than T bands.
- Same blending need as P1 (soft assignment by distance to the two nearest centroids).

### P3. Soft mixture of experts with a learned gate

E experts (E = 4) and a small gate network that outputs weights; train end-to-end with a load-balancing term so no expert is idle. At inference use the top-2 experts.

- Smooth by construction, boundaries are learned.
- Harder to train and to certify; the gate itself can go out of distribution.

### P4. Per-species-group networks

Split the outputs rather than the space: one network for T-controlling major species (CH4, O2, CO2, H2O, CO, H2, N2 balance) and one for radicals and minor intermediates (OH, H, O, HO2, H2O2, CH3, CH2O, ...). Both take the full state as input; outputs are joined before the element projection and T solve, so conservation is kept.

- Targets the dominant error (radicals) without touching the major-species map that already gives good flame T.
- Tests the hypothesis from the fixed-point work: radical accuracy and coupled-T accuracy fight inside one set of weights.

### P5. Residual (boosting) expert for the hard region

Keep the baseline network frozen and add a small correction network trained only on the residual in one region (near equilibrium, or cooled lean gas), switched on by a smooth weight in that region.

- Cheapest way to fix a region without risking the rest. Easy to roll back.
- The correction can be zero outside its region by construction.

### P6. Split by dt band (low priority)

Experts per log(dt) band. Relevant only if the LTS / steady-state work continues (LTS dt 1e-5 to 3.7e-4 s vs the trained 1e-5 to 4e-5 s). Kept as an option, not planned.

## 5. Gate and OOD design

- The gate uses the **input** state of the cell only, never the predicted state.
- Every expert keeps its own OOD tables (T range per Z band, species ranges, VQ-PCA residual, landmark distance), built from the pairs it was trained on. A cell is OOD if it is OOD for the expert(s) that the gate picks.
- For P0/P3: add ensemble disagreement as an extra OOD bit, calibrated on held-out exploration pairs (99.9 % quantile, as the other OOD checks).
- Boundary diagnostics: count cells near a boundary and how often each cell changes expert between steps (a "flip rate"). High flip rate with large output jumps is a red flag.

## 6. Metrics

### Offline (screening, cheap)

- **Stage 18 benchmark**, v2 state set (440 physics-only Cantera states) with all its metrics: one-step increments (inc_T, inc_OH, inc_H, inc_CO), radical ratios, equilibrium fixed point (fp), dT after 10 ms, end-of-run dT, drift over 100 steps; modes alone and hybrid.
- Certification tiers 1 to 3 (stages 08 to 10), cooled and mixing tests.
- **New for this work**:
  - the same metrics broken down per T x Z bin and per expert region, so a win in one region cannot hide a loss elsewhere;
  - a **boundary-crossing rollout set**: 0D trajectories that cross expert boundaries (ignition from 900 K to equilibrium, wall cooling from 2000 K to 500 K), scored for dT and for jumps in dT/dt at the crossing;
  - **continuity**: maximum jump of the predicted increment across a boundary, on a dense line of states.
- Correlation between ensemble disagreement and true error (Spearman) for P0/P3.

### CFD (decision)

- **Protocol v1, pure mode** (no GA18 fallback, because Fluent has none), 0 to 50 ms, extended to 100 ms for the final candidate if the DI reference allows: ignition time, start-up bias, time-mean flame |dT| for T > 1600 K, drift per 10 ms, OH / CO / CH4 / H L1 errors, HRR, OOD share, seconds per step.
- **ITERML score S** = max(flame dT / 5 K, ignition delay error / 0.3 ms, CO/OH log ratio / ln 1.4), so results are on the same scale as ITERML iterations 1 to 3.
- Elitism: a candidate counts as better only if both CFD seeds beat the best baseline by more than the baseline's seed spread.

### Cost

- Microseconds per cell per step in the C core (`fluent/udf/chemmanifold_core.c`), single core, for the same 1000-cell batch, network part and gate part separately. Reference today: about 155 us per cell per 40 us step for one network, vs 590 to 900 us for Cantera CVODES with GA18.
- OpenFOAM seconds per step on 2 and 4 ranks (iter1 pure: about 2 s per step, DI: about 8 s per step).
- Model file size and load time in Fluent (Ansys Student, 4 cores).
- Load balance: with a hard gate, cells in different ranks pick different experts; check that this does not slow down the slowest rank.

## 8. Go / no-go criteria

**After E0 (deep ensemble, no training):**
- Go on with P0 if the 3-seed average beats the best single member by more than the seed spread on the benchmark composite, **or** if disagreement predicts error (Spearman > 0.5 over states). The second case is useful even without an accuracy gain, as an OOD signal for Fluent.
- Otherwise drop P0 as an accuracy tool and keep only the partitioned candidates.

**After E1 (error map):**
- Go on with partitioning only if more than about 60 % of the benchmark error (dT_10ms and OH / CO errors) sits in two or three regions that can be separated by input variables. If the error is spread evenly, partitioning has little to gain; stop and say so.

**After E3 (offline screening), per candidate:**
- Advance to CFD only if all of these hold:
  1. benchmark composite better than **both** matched controls by more than the larger seed spread;
  2. no T x Z region worse than the control by more than 10 %;
  3. boundary-crossing rollouts no worse than the control, and no visible jump at the boundaries;
  4. projected cost at most 1.5x one network for hard gates (P1, P2, P4, P5) and at most 3x for P0 / P3.
- Since the benchmark is not predictive of CFD, it can only **drop** candidates, never declare a winner.

**After E4 (CFD, final):**
- **GO** (adopt the ensemble as the default architecture) if both seeds of the candidate beat the best single-ANN baseline on S by more than its seed spread, with ignition within 0.3 ms of DI, measured cost within the limits above, and no new instability (flip rate, oscillating source terms) in the 50 ms run.
- **Partial GO** if the accuracy gain is real but cost is over budget, or the gain is only in radicals (OH, CO) without a T gain: keep it as an option for pollutant post-processing, not as the default.
- **NO-GO** otherwise. Report it as a negative result with the per-region numbers; that is still a useful finding for the paper.

## 9. Risks and how each is handled

| Risk | Handling |
|---|---|
| Seed noise hides real gains or creates fake ones | 3 seeds offline, 2 in CFD, elitism rule, matched controls |
| Discontinuities at expert boundaries upset the coupled CFD | Overlap plus linear blending; continuity metric; flip-rate monitor in CFD |
| An expert's region has too little data (lean, ignition, psi < 0) | Report pairs per expert before training; fix with targeted physics exploration (new stage 04 seeds or reactors), never CFD data |
| Gate misclassifies near boundaries | Blended boundaries make this a smooth error, not a jump; per-expert OOD tables catch states no expert has seen |
| Benchmark not predictive of CFD | Benchmark only filters; final decision is CFD protocol v1 pure |
| Element / mass conservation with split outputs (P4) | Outputs joined before the existing null-space projection and T solve |
| More models to train, certify, register and load in Fluent | One registry card per ensemble listing member hashes; one v2 model file; selftest covers every expert |
| Cost grows past the budget in Fluent (Student 4-core cap) | Cost limits are part of the go criteria; hard gates evaluate one expert per cell |
| Compute time: E3 + E4 are about 15 h on 4 cores | Warm starts from the baseline; run only after Javier's OK; extra cores (32 to 64) would let seeds run in parallel |

- Averaging independently trained seeds beats **every** member, and the ood6 average beats ood8 too. Averaging warm-started seeds (eqfp8) gives nothing, because those members are almost identical.
- Disagreement predicts error. The Spearman correlation between the members' first-step T spread and the ensemble error is 0.67 to 0.82 at 1 ms and 0.45 to 0.63 at 10 ms. So it works as a short-horizon OOD signal.
- Hybrid mode tells the same story (ens_ood6 20 K at 50 ms vs ood6 27 [20, 33] K, ood8 27 K).
- **Verdict:** go for P0 with members trained from scratch. Strictly, the gain (ensemble 15 K vs best member 22 K) is smaller than the members' spread (22 to 62 K), so the result is "better than any member", not "better by more than the spread". Cost is 3x the network part of the step.
