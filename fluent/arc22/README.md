# ARC_GRI30_NOx22 chemistry in Ansys Fluent

This folder runs the burner in Fluent with the 22-species ARC mechanism reduced from GRI-Mech 3.0. Fluent
transports only the 22 ARC species. A UDF does the chemistry of each cell, with the same steps as the
OpenFOAM ARC run (`openfoam/arcChemStep`):

1. The 21 quasi-steady radicals are solved by linearized QSSA. The rate code is generated from your
   `arc_gri30_nox22.hpp` and is the same arithmetic in plain C.
2. The 22 species and T are integrated at constant pressure and enthalpy over Fluent's chemistry time step
   with a stiff Rosenbrock solver.
3. The elements are projected back onto CO2, H2O, O2 and N2.

The goal is a same-code check: ARC22 against GRI-Mech 3.0, both run in Fluent on the corrected burner.

```
fluent/arc22/
├── udf/
│   ├── arc22_udf.c       Fluent hooks: chemistry step, monitor, load/reload, self-test
│   ├── arc22_core.c/.h   one cell's chemistry step: ODE, Rosenbrock solver, element projection
│   └── arc22_kernel.c/.h ARC rates in plain C (generated by make_c_kernel.py from your .hpp)
├── mechanism/
│   ├── arc22_chem.inp    CHEMKIN species list for Fluent's import (22 species, N2 last)
│   ├── arc22_therm.dat   thermo, copied from your Fluent GRI case
│   └── arc22_tran.dat    transport, copied from your Fluent GRI case
├── arc22.ini             options (optional)
├── arc22_burner.jou      the UDF steps (5 and 6 below) as a journal
├── make_c_kernel.py      .hpp -> arc22_kernel.c
├── make_mixture.py       GRI .cas.h5 -> the three mechanism files
└── tests/                checks outside Fluent (run_tests.sh, check_0d.py, check_cells.py)
```

## What was checked before Fluent

These checks ran on Linux, with gcc and clang, without Fluent.

* **Rates.** They match the C core the OpenFOAM ARC run used to 5e-9.
* **Thermo.** The UDF's enthalpies are the same as those in the CHEMKIN files Fluent imports, to 1e-14.
* **Ignition with 10 µs calls.** Six cases (φ 0.5 to 2.0, 1250 to 1600 K) ignite within 0.72 % of
  Cantera GRI-Mech 3.0, with the same end T (see `tests/CHECKS.md`).
* **Your Fluent GRI solution, cell by cell** (`tests/CHECK_CELLS.md`). I took 300 hot cells and advanced
  each one with the UDF step and with GRI-Mech 3.0 from the full 53-species state. After dt = 1 ms, T
  differs by 0.11 K on average and 1.5 K at most. OH differs by 1.2 % and NO by 1.4 %.
* **Fluent hooks.** They were run through a stand-in `udf.h`: loading, self-test, species matched by name,
  the monitor and its CSV log.
* **Not tested: Fluent itself.** Fluent was not available here, so the GUI steps and TUI commands below
  have not been run.

**Cost per hot cell** (one core, measured on your GRI solution's states). It depends on the chemistry dt
that Fluent passes:

| dt passed by Fluent | 10 µs | 100 µs | 1 ms | 0.1 s |
|---|---|---|---|---|
| ms per hot cell | 0.6 | 0.6–0.9 | 1.2–1.7 | 6.8 |

The case has about 9,600 cells above 1000 K. On 4 cores the chemistry therefore costs about 1.5 to 4 s
per iteration if Fluent's dt is below 1 ms, and about 17 s if it is around 0.1 s. Cold cells cost almost
nothing, because cells below 500 K that barely react take a cheap explicit step. The monitor prints the
real dt and chemistry time after each iteration.

## Before you start

* Use standalone Fluent (Fluent Launcher): **2D**, **Double Precision**, **Processes 4**.
* Use a working folder on a local path without spaces or accents, for example `C:\quemador_arc22`.
* Copy these into that folder:
  * your Fluent GRI case and data: `quemadorUnicoTesis_60KCells-GRI--ID.cas.h5` and `.dat.h5`;
  * the five files in `udf/`;
  * the three files in `mechanism/`;
  * `arc22.ini` and `arc22_burner.jou`.

  All of them are also in the project Library under `chemmanifold/fluent-arc22/`.

## Step by step

### 1. Open the GRI solution and keep a backup of the fields

1. **File > Read > Case & Data…** and pick `quemadorUnicoTesis_60KCells-GRI--ID.cas.h5`.
2. **File > Interpolate…**: choose *Write Data*, then select *Temperature*, *Pressure*, the velocities
   and every *Mass fraction of …*. Click *Write…* and save `gri_fields.ip`. This file is your backup of
   the GRI fields. Step 3 uses it if switching the mixture loses the species.

### 2. Import the 22-species mixture

1. **File > Import > CHEMKIN Mechanism…**
2. *Material Name*: `arc22-mixture`.
3. *Gas-Phase CHEMKIN Mechanism File*: `arc22_chem.inp`.
4. *Thermodynamic Database File*: `arc22_therm.dat`.
5. Tick *Import Transport Property Database*, then *Transport Database File*: `arc22_tran.dat`.
6. Click **Import**. The console should list 22 species and 1 reaction.

The single reaction (H + O2 ⇌ O + OH) is only there so that Fluent keeps volumetric reactions on.
Fluent never uses its rate while the UDF hook of step 6 is set.

### 3. Switch the case to the new mixture

1. **Physics > Models > Species…** (or double-click *Species* in the tree). Keep the model as it is
   (*Species Transport*, *Volumetric* reactions, *Laminar Finite-Rate*, *Stiff Chemistry Solver*,
   *Thermal Diffusion* on). Only change *Mixture Material* to `arc22-mixture`, then click **OK**.
2. Check that the species fields were kept. Open **Results > Contours** and look at *Mass fraction of
   ch4* and *Mass fraction of oh*. If they are zero everywhere, go to **File > Interpolate…**, choose
   *Read and Interpolate*, pick `gri_fields.ip` and click *Interpolate*. That copies T, velocity and the
   22 species back by name. The 31 GRI species that ARC does not carry hold less than 0.1 % of the mass;
   N2, the last species, takes up the remainder.

### 4. Set the same properties as the GRI case

1. **Physics > Materials**, select `arc22-mixture` and click **Edit…**. Set the properties as in your GRI
   mixture:
   * *Density*: incompressible-ideal-gas
   * *Cp*: mixing-law
   * *Thermal Conductivity*: ideal-gas-mixing-law
   * *Viscosity*: ideal-gas-mixing-law
   * *Mass Diffusivity*: kinetic-theory
   * *Thermal Diffusion Coefficient*: kinetic-theory
   * *Absorption Coefficient*: constant 0 (as in the GRI case)

   Click **Change/Create**. The species' own properties (Cp from NASA polynomials, kinetic-theory
   viscosity and conductivity) came with the import.
2. **Physics > Boundaries**. Open each inlet and check its *Species* tab, because the values can be reset
   when the mixture changes:
   * `inlet-fuel`: ch4 = 1.
   * `inlet-coflow-fff-fluid-mixing` and `inlet-coflow-fff-fluid-exterior`: *Specify Species in Mole
     Fractions* ticked and o2 = 0.21. Everything else is 0, and N2 takes the remainder.

   Do the same for the backflow species of the two pressure outlets (`outlet-lab` and
   `wall-fff-fluid-exhaust`): air, o2 = 0.21 by mole.
3. Save as `quemadorUnicoTesis_60KCells-ARC22--ID.cas.h5` (**File > Write > Case & Data…**).

### 5. Build and load the UDF

1. **User-Defined > Functions > Compiled…**
2. Under *Source Files*, click *Add…* and add `arc22_udf.c`, `arc22_core.c` and `arc22_kernel.c`.
3. Under *Header Files*, add `arc22_core.h` and `arc22_kernel.h`.
4. Tick *Use Built-In Compiler*.
5. Click **Build**. The deprecation warnings that appear are harmless.
6. Click **Load**, with the library name `libudf`.

The console prints a line starting with `arc22: ARC_GRI30_NOx22 chemistry … Rosenbrock-W ROS34PW2 …`.

### 6. Hooks, memory, self-test

1. **User-Defined > Memory…**: *Number of User-Defined Memory Locations* = **3**. This is optional, but
   with it the UDF writes the heat release, the steps and the element correction as UDM fields you can
   plot.
2. **User-Defined > Function Hooks…**:
   * *Chemistry Step*: `arc22_chem_step::libudf` (in your GRI case it says *none*).
   * *Adjust*: `arc22_monitor::libudf`.
   * *Execute on Loading*: `arc22_on_load::libudf`.
3. **User-Defined > Execute On Demand…**: pick `arc22_selftest::libudf` and click **Execute**. The
   console must end with `arc22 selftest PASSED`. If it says FAILED, stop and send me the console text.
4. **Solution > Controls** (or the *Species* model's *Integration Parameters*): ISAT must be off. It is
   already off in your GRI case. Leave the rest as in the GRI run.

The journal `arc22_burner.jou` does steps 5 and 6 and then 20 iterations
(**File > Read > Journal…**). Use it only after the case from step 4 is saved and open.

### 7. Run

Continue the steady run exactly as the GRI run: do not initialize, and keep the same solver and
pseudo-time settings.

1. **Solution > Run Calculation**, 20 iterations first.
2. After each iteration the console prints a line like this:
   ```
   arc22: 63087 cells: 13900 integrated (24.0 steps avg, 310 rejected), 49100 quiet, 0 frozen, 0 FAILED;
          chemistry 3.10 s (slowest process); dt 2e-05 - 0.003 s; max element fix 2e-03
   ```
   The same numbers go to `arc22_monitor.csv` in the working folder. Check two things:
   * `FAILED` must be 0. Failed cells keep their old composition for that call.
   * `chemistry … s` is the chemistry time per iteration. Compare it with the total iteration time.
     Send me those two lines if the chemistry takes much longer than about 20 s.
3. Then iterate until the residuals and a few monitors settle (Tmax, the volume above 1500 K, NO at the
   exhaust). That should take about as many iterations as the GRI run needed after its start.
4. Save `quemadorUnicoTesis_60KCells-ARC22--ID.cas.h5` / `.dat.h5` and upload the `.dat.h5`. I will
   compare it cell by cell with the GRI solution (T, OH, CO, NO, N2O and HCN) and with the OpenFOAM ARC
   and GRI runs.

## Options (`arc22.ini`)

Every option has a default, so the file is optional. After you edit it, run `arc22_reload` under
**User-Defined > Execute On Demand…**.

| Key | Default | Meaning |
|---|---|---|
| `rtol`, `atol`, `atol_T` | 1e-4, 1e-9, 1e-3 K | integrator tolerances (rtol and atol as in the OpenFOAM ARC run) |
| `T_freeze` | 200 K | colder cells are not advanced (Fluent GRI case: minimum chemistry temperature 200 K) |
| `T_quiet` | 500 K | below this T, a cell whose whole change over dt is under 1 % of the tolerance takes one explicit step; 0 turns this off |
| `method` | 1 | 1 = ROS34PW2, a Rosenbrock-W method that reuses the Jacobian; 0 = Shampine ROS4 with a new Jacobian every step (like OpenFOAM's Rosenbrock34, about 2 to 5 times slower) |
| `jac_reuse` | 8 | ROS34PW2: at most this many steps per Jacobian; the Jacobian is renewed after a rejected step |
| `project` | 1 | element projection onto CO2/H2O/O2/N2 after each call |
| `write_udm`, `log`, `verbose` | 1, `arc22_monitor.csv`, 0 | outputs |

## Notes

* **Element conservation.** ARC with LQSSA does not conserve elements exactly at rate level, because the
  QSS radicals hold some atoms. Without the projection, carbon drifts by up to 0.8 % per 10 µs call in a
  rich ignition front. The projection puts it back, as in the OpenFOAM run. The monitor shows the largest
  correction each iteration (`max element fix`).
* **Energy.** Fluent computes the heat release from the change in composition. It uses the imported NASA
  polynomials, which are the same ones the UDF uses, so the temperature Fluent recovers matches the
  UDF's T to round-off.
* **Pressure.** If Fluent passes the gauge pressure, the UDF adds the operating pressure (101325 Pa).
* **Parallel.** Each process keeps its own counters. The monitor adds up the counts and reports the
  slowest process's chemistry time.
* To change the mechanism kernel: edit `mechanisms/arc_gri30_nox22/original/arc_gri30_nox22.hpp`, run
  `python fluent/arc22/make_c_kernel.py`, then `fluent/arc22/tests/run_tests.sh`.
